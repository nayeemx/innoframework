Architecture

Innoframework is a Rust-native framework with layered crates, default-deny security, and a single signed CLI. No Node.js required.

Overview

Innoframework follows a layered crate architecture where each layer depends only on the layers below it. The core is dependency-light; adapters and providers are added behind feature gates.

LayerCrateResponsibility
L1innoframework-coreError model, validation, capability authZ, manifest parsing, secret boundary, storage trait, injection screening, output sanitizer, model provider trait
L2innoframework-rpcTyped RPC router, CSRF protection, #[rpc(guard)] proc-macro, error mapping (non-leaky AUD-2001..2008)
L2innoframework-rpc-macroProc-macro for #[rpc(guard = ...)], trybuild compile-fail tests (TR-1.3)
L3innoframework-cliinno init/dev/build/docs, AUD-3001..3013 error codes, Tauri project generation
L4innoframework-agentAgent executor, allowlist tool registry, bounded step loop, injection screening, output sanitization
L5innoframework-uiDioxus 0.7 component kit, tokens, themes, CSS, a11y rules, SSR semantics
P6innoframework-storage-localJSON file-backed storage adapter
P6innoframework-storage-sqlitesqlx-backed SQLite storage adapter
P6innoframework-storage-postgressqlx-backed Postgres storage adapter (feature-gated)
P8innoframework-docs-genRust source documentation generator

Core (L1)

innoframework-core is the dependency-light foundation. It defines:

  • Error model — InnoframeworkError with stable AUD codes, user-facing messages (non-leaky), and optional internal details.
  • Validation — Validate trait with manifest, storage ID, and build target validation.
  • Capability authZ — Fail-checked authorization (TR-3.2).
  • Manifest — inno.toml parsing with deny_unknown_fields, secret boundary scanning.
  • Storage trait (ADR-16) — Boxed-future Storage trait, STORAGE_ERROR (AUD-1600), storage ID validation, typed get/put helpers.
  • Injection screening — Prompt-injection pattern detection (AI-4..AI-9).
  • Output sanitizer — HTML sanitization for model output (AI-9).
  • Model provider — ModelProvider trait with mock implementation (TR-5.2).

RPC (L2)

innoframework-rpc provides typed RPC with fail-closed security:

  • Router — HashMap of route name to boxed-future RpcRoute trait objects.
  • Guard macro — #[rpc(guard = AdminGuard)] enforces guard declaration at compile time.
  • CSRF — Sec-Fetch-Site based protection; missing header fails safe.
  • Error mapping — Non-leaky AUD-2001..2008 errors.
  • Compile-fail tests — trybuild UI tests verify missing guards produce compile errors (TR-1.3).

CLI (L3)

innoframework-cli is the single Rust binary:

  • inno init — Project scaffolding with manifest, Cargo.toml, main.rs, CSP-safe CSS.
  • inno dev — Std-only static server with CSP + nosniff headers.
  • inno build web — Real dx build --platform web --release, emits csp-header.txt.
  • inno build desktop — Tauri 2 project generation + cargo tauri build.
  • inno build mobile — Tauri 2 mobile build, requires signing identity.
  • inno docs — Markdown documentation generator from Rust source.

Agent (L4)

innoframework-agent provides bounded agent execution:

  • Executor — Step loop with max_steps, timeout_ms, max_output_chars limits.
  • Tool registry — Allowlist-only; unknown tools rejected.
  • Injection screening — Input screened before any model call.
  • Output sanitization — HTML sanitized before returning to UI.
  • Mock provider — Testable without external services.

UI kit (L5)

innoframework-ui (Dioxus 0.7):

  • Tokens — Color, space, radius, type, focus, motion design tokens with CSS variable output.
  • Themes — Web and Windows themes with CSS custom properties.
  • CSS — Breakpoints (360/768/1280), focus-visible, reduced-motion, touch-target baselines.
  • Components — 22 components: Button, Input, TextArea, Select, Checkbox, RadioGroup, Switch, Dialog, Popover, Tooltip, Tabs, Table, Form, Toast, Card, Badge, Heading, Text, Link, Divider, Stack, Container, Alert.
  • Layout — AppShell, PageLayout, FormLayout.
  • a11y — Contrast checks (4.5:1), touch targets (44px), SSR semantics.
