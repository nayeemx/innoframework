Security model

Innoframework is built on a default-deny security posture: nothing runs unless explicitly permitted, secrets never ship in manifests, and errors never leak internals.

Overview

Security is not an add-on in Innoframework — it's the default. Every platform API call must be declared in your manifest. Undeclared calls are denied at runtime (fail closed). Build-time checks reject credentials embedded in manifests. All error messages are non-leaky.

Core principles.

  • Default-deny. Nothing runs unless explicitly permitted in inno.toml.
  • Secret boundary. No credentials in manifests or config.
  • Fail closed. Authentication/authorization failures deny access.
  • Non-leaky errors. Error messages never reveal internal state or which check failed.
  • CSP by default. Content-Security-Policy headers on every response.

Default-deny capabilities

Every platform API call must be declared in inno.toml under [[capabilities]]. The framework checks the manifest at build time and enforces at runtime:

LayerCheckBehavior
Build timeManifest parsingUnknown capability IDs rejected; secret values rejected
Build timeTauri config generationOnly declared capabilities mapped to Tauri permissions
RuntimeCapability authZUndeclared API calls denied (fail closed)

Example manifest:

[[capabilities]]
id = "fs.read"
platforms = ["desktop"]
path_prefixes = ["data/"]

[[capabilities]]
id = "notify.send"
platforms = ["desktop"]

Fail closed. If a capability is not declared, the corresponding Tauri permission is not generated and the API call is denied at runtime — even if the underlying platform supports it.

Secret boundary

All manifest values are scanned for credential-like patterns before any build step runs. The following prefixes are rejected (AUD-3004 at the CLI, AUD-1250 at the core level):

PrefixMeaning
AKIA / ASIAAWS access keys
ghp_ / gho_ / ghs_ / github_pat_GitHub tokens
sk_live_ / rk_live_Stripe live keys
xoxb- / xoxp-Slack tokens
sk-ant-Anthropic API keys
-----BEGIN PEM private key blocks
eyJhbGciOiJWT tokens

Never put secrets in inno.toml. Use environment variables or a secret manager. Credential-like values cause a hard parse failure.

Content Security Policy

CSP headers are generated at build time and served with every response — default-deny by design:

Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self';

Additional headers on every response:

  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY
  • Referrer-Policy: no-referrer

style-src allows 'unsafe-inline' for framework/runtime style injection. Prefer external CSS (assets/inno-ui.css) loaded via asset!() + document::Stylesheet.

Auth guards

Routes and RPC endpoints are protected with declarative guards. The #[rpc(guard = ...)] proc-macro enforces that every RPC route declares a guard — missing guards are a compile error (TR-1.3, trybuild compile-fail tests):

#[rpc(guard = AdminGuard)]
async fn delete_user(id: String) -> Result<(), RpcError> { ... }
Guard typeBehavior
AdminGuardRequires admin role
UserGuardRequires authenticated user
PublicGuardNo authentication required

Compile-time enforcement. #[rpc] without guard = produces error: "rpc route must declare a guard: #[rpc(guard = AdminGuard)]"

CSRF protection

Cross-site request forgery is mitigated via the Sec-Fetch-Site header:

Sec-Fetch-SiteBehavior
same-origin / same-siteRequest passes
Cross-siteRequest denied (403)
MissingRequest denied (fail safe)

AI agent security

The P7 AI agent runtime includes multiple safety layers:

LayerMechanism
Input screeningPrompt-injection patterns detected before any model call (instruction override, role override, prompt leak, jailbreak, safety bypass)
Output sanitization<script>, <iframe>, event handlers, and javascript: URLs removed; all HTML escaped
Tool allowlistOnly registered tools can be called; unknown tools rejected
Template substitution{{placeholder}} only — no raw user input in system prompts
Step limitsmax_steps enforced; unbounded loops prevented
Timeouttimeout_ms per provider call
Output truncationmax_output_chars on final output

Threat model

The full threat model is documented in docs/THREAT_MODEL.md with threats TM-1 through TM-10 covering: secret leakage, capability escalation, XSS via model output, prompt injection, CSRF, error information leakage, and supply-chain compromise.
