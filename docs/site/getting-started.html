Getting started

Install the Innoframework CLI, scaffold your first Dioxus 0.7 app, and build it for web, desktop, or mobile — no Node.js required.

On this page
  • Install the CLI
  • Scaffold your app
  • Run the dev server
  • Declare capabilities
  • Build for production
  • Troubleshooting

1. Install the CLI

Innoframework ships as a single Rust binary. Install it with cargo install:

cargo install innoframework-cli

Verify the installation:

inno --version

Prerequisites. You need the Rust toolchain (1.80+) and, for web builds, the Dioxus CLI (cargo install dioxus-cli --version 0.7.10). For desktop/mobile builds, you also need cargo tauri (cargo install tauri-cli --version 2.11.4).

2. Scaffold your app

Create a new project with inno init. The wizard prompts for a name and platform targets, or you can skip prompts with -y:

# Interactive wizard
inno init --name my-app

# Or skip all prompts with defaults
inno init --name my-app -y

This creates:

  • inno.toml — project manifest (targets, capabilities, auth, data backend)
  • src/main.rs — Dioxus 0.7 entry point
  • assets/inno-ui.css — CSP-safe shared stylesheet
  • Cargo.toml — Rust crate definition

Enter the app directory:

cd my-app

3. Run the dev server

Start the development server with CSP and X-Content-Type-Options: nosniff headers on every response:

inno dev --port 4173

Open http://127.0.0.1:4173 in your browser. The server serves from the Dioxus public directory and applies the CSP header automatically.

Default port. If you omit --port, the server listens on 8080.

4. Declare capabilities

Open inno.toml and list the platform APIs your app needs. Undeclared calls are denied at runtime (fail closed):

[project]
name = "my-app"
version = "0.1.0"
targets = ["web", "desktop"]

[auth]
method = "session"

[[capabilities]]
id = "fs.read"
platforms = ["desktop"]
path_prefixes = ["data/"]

[[capabilities]]
id = "notify.send"
platforms = ["desktop"]

[[capabilities]]
id = "keychain.get"
platforms = ["mobile"]

Available capability IDs: fs.read, fs.write, notify.send, keychain.get, keychain.set, dialog.open, dialog.save, shell.execute.

5. Build for production

Web

Compiles to WASM with Dioxus 0.7 and emits a csp-header.txt beside the output:

inno build web

Output: target/dx/<app>/release/web/public/ — serve with the CSP header.

Desktop (Tauri 2)

Generates Tauri project files from your manifest capabilities, then builds:

inno build desktop

Mobile (Tauri 2)

Requires a signing identity set in inno.toml (signing is deferred per ADR-09):

[build]
signing-identity = "my-dev-cert"
mobile-target = "android"
inno build mobile

Troubleshooting

ProblemCauseFix
the `dx` tool was not found Dioxus CLI not installed cargo install dioxus-cli --version 0.7.10
the `cargo tauri` command was not found (AUD-3009) Tauri CLI not installed cargo install tauri-cli --version 2.11.4
manifest does not declare the desktop target (AUD-3010) inno.toml missing desktop in targets Add "desktop" to the targets list
mobile build requires a signing identity (AUD-3013) No signing-identity in [build] Set signing-identity in inno.toml
secret embedded in manifest (AUD-3004) Credential-like value in inno.toml Remove the secret; use environment variables instead
