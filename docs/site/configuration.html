Configuration (inno.toml)

The manifest is the single source of truth for a generated project: name, version, targets, capabilities, auth, data backend, AI provider, and build settings. Unknown fields are rejected (deny_unknown_fields).

Overview

The inno.toml file is parsed with deny_unknown_fields, so any typo in a section or key produces a parse error (AUD-1210). All string values pass through the secret boundary check — credential-like values are rejected at parse time (AUD-1250).

Full example

[project]
name = "my-app"
version = "1.0.0"
targets = ["web", "desktop", "mobile"]
signing-identity = "my-dev-cert"
mobile-target = "android"

[data]
backend = "sqlite-dev"

[ai]
provider = "none"

[auth]
method = "session"

[build]
signing-identity = "my-dev-cert"
mobile-target = "android"

[[capabilities]]
id = "fs.read"
platforms = ["desktop"]
path_prefixes = ["data/"]

[[capabilities]]
id = "fs.write"
platforms = ["desktop"]
path_prefixes = ["data/", "logs/"]

[[capabilities]]
id = "notify.send"
platforms = ["desktop"]

[[capabilities]]
id = "keychain.get"
platforms = ["mobile"]

[[capabilities]]
id = "keychain.set"
platforms = ["mobile"]

[[capabilities]]
id = "dialog.open"
platforms = ["mobile"]

[project]

KeyTypeRequiredDescriptionExample
name string Yes Project name. Lowercase ASCII, digits, and dashes only. "my-app"
version string Yes Semver (X.Y.Z), no pre-release. "1.0.0"
targets array of strings Yes Build targets: web, desktop, mobile. At least one required. ["web", "desktop"]
signing-identity string No Signing identity for mobile builds (ADR-09 deferred — unsigned bundles only). "my-dev-cert"
mobile-target string No Preferred mobile target: android or ios. "android"

targets

Declares which platforms to build for. Each target maps to a Rust target triple and bundle format:

TargetTripleBundle formatCommand
webwasm32-unknown-unknownWASMinno build web
desktopx86_64-pc-windows-msvcMSI / DMGinno build desktop
mobileaarch64-linux-android / aarch64-apple-iosAAB / IPAinno build mobile

Mobile requires a signing identity. If mobile is in targets but signing-identity is not set, the build fails with AUD-3013.

[[capabilities]]

Declares platform API access. Each capability is fail-closed: undeclared capabilities are not available at runtime.

KeyTypeRequiredDescription
id string Yes Capability identifier (see table below).
platforms array of strings Yes Platforms where this capability applies: web, desktop, mobile.
path_prefixes array of strings No File-system path prefixes for fs.read/fs.write scope.
Capability IDDescriptionPlatformsTauri permission
fs.readRead files and directoriesdesktop, mobilefs:read-file, fs:read-dir, fs:read-text-file, fs:copy-file
fs.writeWrite, create, delete, rename filesdesktop, mobilefs:write-file, fs:create-dir, fs:delete-file, fs:rename-file
notify.sendShow desktop notificationsdesktopnotification:show
keychain.getRead credentials from keychainmobilekeychain:get
keychain.setWrite credentials to keychainmobilekeychain:set
dialog.openOpen file picker dialogmobiledialog:open
dialog.saveShow save file dialogmobiledialog:save
shell.executeExecute shell commandsdesktopshell:execute

Fail closed. Capabilities not declared in [[capabilities]] are not exposed. Web-only capabilities are excluded from desktop/mobile builds and vice versa.

Secret boundary

All manifest values are scanned for credential-like patterns before any build step runs. The following prefixes are rejected (AUD-3004):

PrefixMeaning
AKIAAWS access key ID
ASIAAWS temporary access key ID
ghp_GitHub personal access token
gho_GitHub OAuth token
ghs_GitHub server token
github_pat_GitHub fine-grained token
sk_live_Stripe live secret key
rk_live_Stripe live restricted key
xoxb-Slack bot token
xoxp-Slack user token
sk-ant-Anthropic API key
-----BEGIN PEM private key block
eyJhbGciOiJWT token

Never put secrets in inno.toml. Use environment variables or a secret manager instead. The manifest is scanned at parse time and credential-like values cause a hard failure.

Validation rules

  • Name: non-empty, lowercase ASCII letters/digits/dashes only.
  • Version: exactly three dot-separated numeric components (X.Y.Z).
  • Targets: at least one; each must be web, desktop, or mobile.
  • Mobile: requires signing-identity to be set.
  • Capabilities: each ID must be known; unknown IDs are rejected.
  • Secret boundary: no credential-like prefixes in any value.
  • Unknown fields: rejected with deny_unknown_fields.
