What Innoframework does

A full-stack Rust framework with secure defaults, from the CLI to the compiled app.

Typed server functions

Call server-side Rust functions from the client with full type safety — no manual API contracts to maintain.

File-based routing

Place files in the routes directory and they become pages automatically — no router configuration required.

Auth guards

Protect routes and RPC endpoints with declarative guards. Fail-closed by default — undeclared access is denied.

Default-deny capabilities

Every platform API call must be declared in your manifest. Nothing runs unless explicitly permitted.

Secret boundary

Build-time checks reject credentials and secrets embedded in manifests or config before they ever ship.

CSP presets

Content-Security-Policy headers are generated at build time and served with every response — default-deny by design.

Build once, target everywhere

One manifest, one build command — output for web, desktop, and mobile from the same codebase.

How it works

Three steps from empty folder to a compiled, CSP-secured app.

1

Initialize a project

Run inno init --name my-app to scaffold a Dioxus 0.7 app with a manifest, routing, and a CSP-safe stylesheet.

2

Declare capabilities

List the platform APIs your app needs in inno.toml. Undeclared calls are denied at runtime (fail closed).

3

Build and serve

Run inno build web to compile WASM with dx and emit a CSP header, or cargo tauri build for desktop/mobile.

Get started

Install the CLI and scaffold your first app.

# Install the Innoframework CLI
cargo install innoframework-cli

# Scaffold a new app
inno init --name my-app -y

# Enter the app directory
cd my-app

# Start the dev server (serves with CSP + nosniff headers)
inno dev --port 4173

# Build for web (real `dx build --platform web --release`)
inno build web
