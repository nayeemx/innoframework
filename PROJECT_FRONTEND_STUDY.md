## 2. Per-project notes

### 2.1 innofinance (finance PWA, v1.12.0)
- Scripts reveal the product: `build:extension` (a browser extension build from the same codebase), `emulators` (Firebase emulator suite), `test:rules` (Firestore security-rules tests), `icons` (PWA icon generation via to-ico and @resvg/resvg-js), `bump` (version release script).
- Dependencies cover finance and reporting: xlsx, jspdf + jspdf-autotable, pdfjs-dist, Dexie for offline storage, recharts, leaflet (location), i18next (multi-language), otpauth (TOTP), qrcode.react, nodemailer (listed as a dependency, which is unusual for a client bundle; should be verified as server-only).
- Client bundle risk: `nodemailer` and `firebase-admin` both appear in `dependencies` (not devDependencies). `firebase-admin` in a browser app would pull Node-only code. Worth verifying it is not imported from client code.
- Three server runtimes: Firebase Functions (nodejs18), Netlify Functions (esbuild bundled), Cloudflare Worker (cron digest). See backend study.
- Tests: about 80 Vitest test files in one `src/test/` directory, covering finance logic, reminders, extension messaging, Android manifest checks, AI helpers, and route smoke tests. Strongest unit-test coverage in the workspace.

### 2.2 OPMS (operations system, v0.20.0)
- Most current stack in the workspace: React 19.2, Vite 8, TypeScript 6, Tailwind 4, Zod 4, react-router 7, i18next 26, Vitest 4, Playwright 1.62.
- Scripts describe the test pyramid explicitly: `test:data`, `test:guard`, `test:guard-roundtrip`, `test:unit`, `test:e2e`, `test:render` (in English and Bangla), `test:arch`, `test:rules`, `test:pentest`, `test:probe`. The `pentest` and `probe` scripts indicate security testing against a running instance.
- `screenshots` and `screenshots:bn` scripts generate visual docs in two languages.
- Netlify: `/api/*` rewrites to a `guard` function, everything else to SPA. The guard function is an access-control layer in front of the API.
- Files go to AWS S3 via presigned URLs (`@aws-sdk/s3-request-presigner`), so the browser uploads directly and the server only signs.
- Dev-only tooling in `dependencies`: none obvious. `esbuild` and `tsx` are dev-scoped.

### 2.3 portfolio
- Declares CV generation (`build:cv` script). Likely renders a PDF or HTML CV at build time; not inspected.
- Contact form uses EmailJS from the browser (no backend). Its CSP explicitly allows `api.emailjs.com` only, which is a good minimal-allowlist example.
- Strict security header set in netlify.toml: frame-ancestors none, object-src none, form-action self, HSTS preload, Permissions-Policy disabling camera/mic/geo. Good reference for a secure default header set.
- `lovable-tagger` in devDependencies: a Lovable (AI app builder) integration. Lovable scaffolding is also visible in my-vps and other projects.

### 2.4 fleet-vue-v2.0
- Name says Vue; the actual code is Next.js 15 + React 19 (the "vue" is a historical name). Generated from a v0-style scaffold (`my-v0-project`).
- Uses unpinned `latest` for date-fns, jspdf, and sonner. Non-reproducible builds.
- Mixes exact pins (`1.2.2`) with caret ranges, indicating inconsistent dependency hygiene.
- Backend is Appwrite (client `appwrite` and server `node-appwrite`). Appwrite is a self-hostable Firebase alternative (see FRAMEWORK_ENGINEERING_FUNDAMENTALS.md section 8).

### 2.5 Open_Erp (ERP, v0.0.0)
- Most ambitious frontend in the workspace. Module-based ERP: HR, FICO (finance), SD (sales and distribution), MM (materials), MFG (manufacturing), plus archive and setup screens. Test names confirm the modules (see rust/testing study).
- Stack is current: React 19.2, Vite 8, TanStack Router 1.170 (file-free, code-defined routes), TanStack Query 5, TanStack Table 9, shadcn 4 CLI, Tailwind 4, Bun for scripts.
- netlify.toml documents a real production bug: without an explicit `/api/*` rewrite, Netlify returns index.html with status 200 for API paths, and the bootstrap check parsed HTML as JSON. The comment explains the ordering rule: redirects are evaluated top to bottom, so API rules must precede the SPA catch-all. This is a concrete lesson a framework should encode (routing precedence and typed API boundaries).
- Scripts show strong project discipline: `check:secrets`, `check:imports`, `check:encoding`, `check:rls` (Supabase row-level security checks), `check:nav` and `nav:sync` (navigation config consistency), `check:legacy-archive`, `arch` (architecture tests), `verify` (combined gate).
- Supabase in production: `db:push`, `db:reset`, `db:list` manage migrations. `recover:super-admin` is an operational break-glass script.
- `extract:sd`, `extract:fico`, `extract:legacy` suggest data migration from legacy systems into module archives.
- Playwright config deliberately uses a preview build on port 4173 (see testing study).

### 2.6 baishakhix
- Largest rich-text surface: 13 Tiptap extensions (color, highlight, image, link, mention, tables, task lists, text-align, underline). Tiptap v2 is pinned here; v3 is current (see SECOND_PASS_CATALOG.md).
- Barcode and QR: @zxing/browser and @zxing/library for scanning; bwip-js for generating barcodes.
- Documents: jspdf + jspdf-autotable for PDF, react-to-print for printing, papaparse for CSV, xlsx pinned to a SheetJS CDN tarball (`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`) rather than npm. Reason: npm `xlsx` was unpublished from the registry for a period; the CDN tarball is a supply-chain tradeoff to note.
- `pgsql-ast-parser`: parses SQL in the browser. Unusual; suggests a SQL editor or query builder feature.
- Dev/prod split: Docker compose for local dev on port 5173 with node_modules kept in an anonymous volume (correct pattern), Netlify for production.
- `vite-plugin-pwa` in devDependencies: PWA support.
- `firebase-tools` in devDependencies with a `deploy:functions` script.

### 2.7 edutech (two apps in one folder)
- `edutech/edutech`: antd 5 (Ant Design) + Tailwind 4 + framer-motion + swiper + echarts. Uses `@dnd-kit` for sortable lists, `react-player` for video, `react-date-range` and `react-datepicker` for date input, `country-flag-icons`, `crypto-js` (client-side crypto; review whether it is used for secrets).
- Vite devDependency is `^6.1.0` but `@vitejs/plugin-react` is `^1.3.2`, a major-version mismatch (plugin 1.x targets older Vite). Likely a build-time problem; not verified by running.
- `edutech/redux47/redux-frontend`: Redux Toolkit + Stripe + Firebase + Netlify. Stripe payments on the client; checkout intent must be created server-side (see redux-backend).
- `edutech/backup`: earlier copy with antd and react-player (snapshot; not active).

### 2.8 innology-treding (trading/finance dashboard)
- React 19 + Vite 7 + TypeScript 5.8, Redux Toolkit, react-modal, recharts 3.
- Document generation heavy: html2canvas (DOM screenshot), jspdf + jspdf-autotable + jspdf-font (custom fonts for PDF text, relevant for Bangla), pdfjs-dist (reading PDFs), xlsx.
- Netlify config only does SPA fallback; no security headers or caching rules, unlike portfolio.

### 2.9 Astha_feed_industries v0.4.2 (largest real-time frontend)
- Most dependencies in the workspace (about 45 runtime packages). Feature surface inferred from packages:
  - Data grids and spreadsheets: @univerjs (preset-sheets-core, presets, sheets-conditional-formatting) — a full spreadsheet engine in the browser; exceljs and xlsx for import/export; jszip for archives.
  - Realtime video and audio: LiveKit (components-react, client, server SDK) plus PeerJS and Metered TURN (@metered-ca/realtime). Two different WebRTC stacks in one app.
  - Maps: leaflet and react-leaflet 5.
  - Drag and drop: @hello-pangea/dnd.
  - Organization chart: react-organizational-chart.
  - Device and network identity: @fingerprintjs/fingerprintjs 5, ipify, public-ip.
  - Offline persistence: localforage and redux-persist 6.
  - Date parsing: chrono-node (natural-language dates).
- `patch-package` and a `postinstall` script: patches to third-party packages are applied after install. Indicates a dependency that needed a local fix.
- Release tooling in scripts: `release:patch|minor|major`, `version`, `postversion`, `rollback`, `reconcile`. Full versioned release flow.
- Distribution-support admin scripts (delete, export, backfill, inspect, promote superadmin): a data-operations toolkit.
- Netlify: `/api/:collection` rewrites to a `distribution-api` function with force=true. Cache-Control no-store on all pages; assets are immutable.
- `vite-plugin-basic-ssl`: local HTTPS for WebRTC/geolocation, which browsers require to be secure contexts.
- Security note: the Netlify config comments that the Firebase project id is public and is bundled deliberately, using SECRETS_SCAN_OMIT_KEYS to avoid a build failure. The explanation is correct (Firebase web config is public), but the pattern hides a real leak class; keep scanning enabled for true secrets.

### 2.10 ostad/blog-project and figma to code/shopery
- Both are Next.js 14 with Tailwind 3 (older generation). Next 14.1 and 14.0 are behind the current App Router defaults used in vps/web (Next 15) and innology-vps-panel (Next 16).
- eslint 8 and eslint-config-next 14, versus eslint 9 in newer projects.
- `nextjs-toploader` (ostad) is a route-progress bar for the App Router.

### 2.11 extension/innocapture v2.0.0
- Browser extension. Test scripts: `test:unit`, `test:browser` (Playwright), `test:package` (checks the packaged output). A three-level test pipeline for extension packaging: unit, real browser, packaged artifact. Good pattern to reuse for any extension in a custom framework.
- `package` script produces the store artifact.

### 2.12 nayeem bangla, react-scss, sneat-1.0.0
- nayeem bangla: small React 18 + Vite 5 landing page with type animation; Bangla text.
- react-scss: SCSS exercise; sass 1.76 with React 18.
- sneat-1.0.0: a legacy Bootstrap admin template built with Gulp 4 and webpack 4 (2019–2020 toolchain). Useful as an example of the old build stack that Vite replaced. Node compatibility of webpack 4 with modern Node is a known problem; not verified by running.

## 3. Cross-project patterns

### 3.1 Framework and build generations
- React 19 is the default for new work (OPMS, Open_Erp, baishakhix, edutech, treding, Astha). React 18 is still used in innofinance, portfolio, and nayeem bangla.
- Vite 8 (OPMS, Open_Erp) and Vite 7 (Astha, treding, imrul-ui-v2) are the current generation. Vite 5 is in older projects.
- Tailwind 4 (CSS-first, `@tailwindcss/vite`) in newer projects; Tailwind 3 with `tailwind.config.js` in innofinance, portfolio, ostad, shopery, and nayeem bangla.
- Next.js 14 (ostad, shopery), 15 (fleet-vue, vps/web), 16 (innology-vps-panel).

### 3.2 Routing approaches (4 styles in use)
- react-router-dom 6 (innofinance, portfolio, nayeem bangla).
- react-router 7 (OPMS, baishakhix, edutech, treding, Astha). Same API family, merged packages.
- TanStack Router 1 (Open_Erp only): code-defined, type-safe, search-param validation.
- Next.js App Router (fleet, vps/web, innology-vps-panel): file-system routes plus server components.

### 3.3 Server state and data layer
- TanStack Query 5: innofinance, portfolio, OPMS (no; uses react-hook-form only), baishakhix, Open_Erp, fleet (no), my-vps frontend.
- Redux Toolkit 2: baishakhix, edutech redux-frontend, treding, Astha (with redux-persist), innology-web.
- Local persistence: Dexie (innofinance), localforage (Astha), redux-persist (Astha).
- Two competing server-state patterns (TanStack Query vs Redux) appear in the same workspace. The second-pass catalog already recommends picking one.

### 3.4 Forms and validation
- react-hook-form + zod (or @hookform/resolvers): innofinance, portfolio, OPMS (zod 4 with resolvers 5), fleet, Open_Erp (via the shadcn form pattern), my-vps.
- OPMS is the only project on zod 4 and @hookform/resolvers 5; the others are on zod 3 and resolvers 3. Migration is needed to share schemas.

### 3.5 UI kits
- Radix primitives + shadcn-style components + Tailwind: innofinance, portfolio, fleet, Open_Erp (shadcn 4 CLI), my-vps.
- antd 5: edutech only.
- Headless UI 2 (Tailwind Labs): baishakhix only.
- Bootstrap 5: sneat (legacy).
- No UI kit, custom components: OPMS, treding, Astha (Tailwind directly, lucide and react-icons).

### 3.6 Deploy target
- Netlify is the default for every SPA: innofinance, OPMS, portfolio, Open_Erp, baishakhix, edutech, treding, Astha. Netlify config files are present in nearly all frontends.
- Firebase Hosting is configured through firebase.json in innofinance, OPMS, baishakhix, Astha (rules and functions; hosting not always used).
- Vercel is used only for a backend (edutech redux-backend).
- Docker is used only for local development (baishakhix).

### 3.7 Testing maturity (frontend)
| Level | Projects |
|---|---|
| Unit + E2E + architecture | OPMS (Vitest + Playwright + arcovia + pentest scripts), Open_Erp (Vitest + Playwright + arch + nav checks) |
| Unit only, extensive | innofinance (~80 files) |
| Extension pipeline (unit, browser, package) | innocapture |
| Basic or none | portfolio (lint only), treding, Astha, baishakhix, edutech, fleet, shopery, blog |

### 3.8 Security headers and CSP
- Full header set (CSP, HSTS, frame-ancestors, Permissions-Policy): portfolio (strongest explicit CSP in the workspace).
- Partial (X-Frame-Options, nosniff, Referrer-Policy): innofinance.
- Cache-only config: edutech, baishakhix, Astha (no-store and immutable rules).
- None: treding, fleet, shopery, blog, nayeem bangla (not inspected for netlify config; none found in manifests).

### 3.9 Dependency hygiene
- Unpinned `latest` (fleet: date-fns, jspdf, sonner).
- Git or CDN tarball dependency (baishakhix: xlsx from SheetJS CDN).
- Patch-package post-install hook (Astha).
- Mismatched plugin and Vite major (edutech: plugin-react 1.x with Vite 6).
- Duplicate capability across projects (xlsx 0.18 in several, 0.20 in baishakhix; jspdf 3, 4, and 5 across projects).

## 4. Relevance to a custom framework

What the workspace repeatedly rebuilds, and therefore what a framework could own:
1. Authenticated routing with a guard layer (OPMS guard function, Open_Erp route checks, Astha distribution API).
2. Typed API boundary between SPA and functions (Open_Erp `/api/*` rewrite lesson, Astha `/api/:collection`).
3. Offline persistence and sync (Dexie, localforage, redux-persist).
4. Document generation: PDF, XLSX, CSV, print, barcode and QR (innofinance, baishakhix, treding, Astha). Currently 4 libraries for overlapping jobs.
5. Realtime and media: LiveKit, PeerJS, and Metered TURN in one app (Astha); socket.io elsewhere.
6. Release and versioning scripts (Astha `release:*`, innofinance `bump`).
7. Security header presets (portfolio is the template).
8. Extension and PWA builds from one codebase (innofinance `build:extension`, vite-plugin-pwa in several).

Honest gaps (not inspected): component and store source, the Netlify functions folders, vite.config files, and the Next.js routing folders of ostad and shopery.
